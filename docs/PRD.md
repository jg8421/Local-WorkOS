# Local WorkOS 产品需求文档（PRD）

> 文档日期：2026-10-04；应用版本：1.9.1；本文对应自然语言追问、统一模型连接、多轮修订、产物归档、自动整理、质量流程与后台执行。
> 本文区分「当前代码已实现」「已经实测」「拟新增」。未经验证的愿景不等于现有功能。
> 接手开发先读 [AI 工程交接指南](<AI_HANDOFF.md>)；开发源码位于 [仓库根目录](<../>)。本文是公开版，部署域名用示例代替。

## 1.9.0 · 用自己的话工作，缺少条件时继续对话

- 首页任务理解使用所选模型进行语义规划，识别研究材料、会议、财务和项目整理，不要求精确关键词。确定用途可直接选择工作类型；实质歧义只追问1–3个必要条件。任务理解本身不执行操作、不读取全库或模型外的文件。
- 问答、行动、工作材料、会议和估值都显示统一的 `needs_input` 补充提示，保留原任务、所选模型、项目和资料范围。用户可以直接用自然语言补充，也可点选建议；认证、范围冲突、停止和模型服务故障保留各自处理方式，不伪装成缺少条件。
- 财务先保留已知假设，再确认缺失币种、金额单位、期间、预测和交易条件。明确的“20%”“12倍”和数字字符串可识别；不会把普通数字20猜为20%、替用户选择日期或把未知值补零。负利润P/E、WACC与增长率冲突、LBO持有期不匹配等给出具体口径问题；算术仍使用原确定性引擎。
- 已创建对话的追问及假设快照可继续讨论；补充轮次不被当作成功交付稿。需要补充的任务不保存不完整交付，重新提交使用新请求编号；已经完成的操作记录保留，取消不会回滚它们。项目、用途、资料和修订父稿范围仍严格验证。
- 所有新 AI 工作默认 WorkBuddy 桥接的 DeepSeek V4.1 Flash，用户已有偏好保留；本地原文检索和规则纪要仍为明确的非AI选项。旧API兼容默认值与界面新任务默认不同，不自动覆盖已有客户端约定。
- 设置可登记多个兼容模型。连接身份由服务地址和上游模型ID组成；同一ID连接不同服务时分开显示、分开调用，密钥不串用。定义保存在私有 `custom-models.json`，API key只在运行进程内存，重启后需重填；定义和业务路径不进入公开仓库或记录镜像。移除连接后不能继续用旧选择调用。
- 首页“使用指南与案例”说明各类工作的自然语言例子、资料要求和能力边界。读取指南、模型目录和自定义定义列表不调用模型；公网仍需登录。模型检测仅发送合成请求。

## 1.8.0 · 一个模型选择框，所有 AI 工作共用

- 首页、资料问答、工作区操作、工作材料、会议、估值及设置使用同一服务端目录，按 GPT、DeepSeek、GLM、Kimi、Hunyuan、账户桥接别名及兼容接口分组。每处只保留一个模型框，不另设供应商框；保留各用途偏好及旧 GPT 偏好。
- 安装目录含8个GPT、桥接目录含22个聊天选项及8个补全专用项。已审阅新桥接别名不因旧 `/models` 漏项被误禁用；补全项可见且不可用于聊天。目录不是权限保证，真实请求验证后显示可用/失败，失败可在设置重新检测。
- 估值、纪要和行动助手已支持同一组模型；选定服务与模型同时校验，冲突拒绝，不静默切换。估值仍由本机确定性公式计算，模型只抽取假设。API旧请求省略服务时按已知模型身份推断；无模型的旧估值请求保留DSH默认。
- 检测只发送合成JSON，不读取业务记录；检测可停止，GET列表不调用模型。状态仅在本机缓存24小时并绑定非秘密服务指纹，不包含密钥。桥接响应通常回显请求ID，不能据此独立确认实际后端型号。

## 1.7.0 · 能继续修订的 AI 工作与项目产物

- 问资料、工作区操作、交付生成、纪要和假设整理统一显示阶段、实际耗时、预计时间范围和执行记录。预计时间来自任务类型的预设范围，排队和超时无法可靠估计时明确说明；仅已完成的工作步骤用于计算进度，不虚构模型 token 百分比。记录展示可核验步骤、工具和资料范围，不输出或保存模型私有思维链。
- 各入口支持新对话、选择历史和继续修订。对话持久保存于本机 SQLite，按工作区、项目、用途、所选资料集合及会议/模型方法/工作类型验证范围。换资料开启新讨论，旧对话须明确选择恢复；记忆不进入外部模型上下文。失败或停止的轮次可见，但不作为成功模型上下文。历史受长度预算限制，截断必须提示。
- 问答只保存讨论历史，不自动创建项目结论文件。纪要以同一会议原文为依据，并读当前手动修改的纪要；模型整理读当前 JSON 假设，保留未要求改变的字段。生成期间的手动纪要编辑不会被迟到输出覆盖。
- 交付修订读当前已保存正文，生成带父稿关联和递增版本的新记录，原稿保留。原稿资料范围须保留，排队时固定原稿及上下文签名；两者发生变化须重新提交。财务模型按当前假设继续计算，不用文本改稿代替确定性计算。
- 本机设置项目根目录后，只扫描文件夹名称进行有界匹配；唯一强匹配自动关联，重名或未完成扫描显示候选/待确认，无匹配使用本机托管目录。运行配置及业务路径不进入公开源码。远程页面不能配置根目录或绑定任意路径，演示区只写托管目录。
- 新生成或保存的交付、纪要、笔记及助手创建资料自动归档至项目下的 `WorkOS产物`。内容相同重试复用归档，变化生成新版本，不覆盖原件；文本交付生成 HTML/DOCX/PPTX/Markdown，纪要生成 HTML/DOCX，结构化财务模型另导出公式 XLSX。显示实际文件、目录、哈希及失败状态；导出失败保留数据库成果，重试只重做文件导出。云端上传完成不由本机保存状态推断。

## 1.6.1 · 问资料始终使用所选模型

- “问资料 · 不改记录”默认调用 DeepSeek，也可选择 GPT/DSH 或其他兼容模型。关键词未命中不再跳过模型；提供仅来自明确勾选资料的真实段落节选，总正文预算24000字符，各资料公平分配，保留页码/段落和可定位引用。节选不意味着全文已读或内容已经相关。
- 默认2–4句话或最多3个要点简要解释；用户指定篇幅或结构时遵从。资料不足时，可标明“一般解释”并说明缺口，不把概念推断写成公司事实、不虚构来源或数字。空正文也调用模型解释缺口；不存在的引用仍被拒绝。
- 显示实际调用模型，不把未命中误标为本地回答；连接不可用时保留输入并显示错误，不静默降级。本地“仅找原文 · 不调用AI”仍是明确的可选模式，个人记忆不外发；选中记忆不会自动改变引擎。问答不自动创建项目成果记录，回车和停止继续适用。

## 1.6.0 · 回车发送与随时停止

- 首页需求及研究助理的问答、工作区操作和交付草稿输入统一 Enter 发送、Shift+Enter 换行；中文输入法确认、长按和组合键不会误发送。正文、纪要、逐字稿及 JSON 编辑保留原来的换行行为。
- 运行时输入区提供“停止”；页面上方的运行栏及后台任务卡可在导航后停止对应工作。保留输入和材料选择，重新发送使用新的请求编号。停止确认失败会保留“重试停止”，不冒充已取消。
- 浏览器停止等待，服务端取消排队/运行任务，阻止之后的模型轮次、行动和保存，忽略晚到的回复。已提交的本地操作及已保存草稿保留并报告；会议生成和自动保存合为服务端受保护的提交，并防止覆盖期间的新编辑。
- DSH 进程可中断。兼容模型已发出的网络请求可能仍等待返回或超时；停止不能保证撤回模型服务已接收的请求，但迟到结果不能继续执行或保存。取消标记按工作区隔离并有容量/有效期限制。

## 1.5.3 · 过期会话自动恢复

- 服务发布/重启或其他页面重新登录造成 CSRF 令牌过期时，同工作区读取最新令牌并重试原请求一次，保留当前输入和页面。并发请求共享会话更新。
- 仅服务器明确返回 `403 / csrf_expired` 且尚未执行写入或调用模型时恢复。普通权限错误、登录失效和不确定的网络失败不自动重发；工作区已切换或请求已取消时停止重试。

## 1.5.2 · 首页直接新建项目

- “今天要完成什么？”中的关联项目下拉菜单提供“新建项目”，旁边也有直接入口。填写名称即可创建，其他项目资料默认折叠，创建后自动选中以继续当前工作。
- 保留当前工作要求、用途和已有资料记录；取消保留此前项目选择。已有项目/研究页的资料范围和关联关系保持各自明确的项目选择。

## 1.5.0 · 可检查的质量流程与后台执行

- 1.5.1 关闭服务时先将未完成任务标为中断，再停止接受执行和保存；旧模型调用返回也不能晚写状态或交付。接口拒绝额外字段，凭证不能塞进任务快照。
- 同一输入区选择快速草稿/深入整理；DD、IC、讨论、技术、协议、版本对照和模型审阅默认深入模式。深入模式增加独立模型调用复核、最多一次针对问题的修订和再次复核。
- 检查非空、正常结束、引用标签、明确表格/问题数量/篇幅、覆盖声明及财务口径标签。模型复核提供有原文位置和来源标签的意见，不能认证事实。未闭合的阻断问题不保存；普通风险/资料不足保存为待审阅。
- 后台固定要求、选定资料和非秘密模型配置的指纹；接受后可以继续输入和导航。刷新恢复，断线不假定任务失败。进程重启后的未完成任务可显式重试；已保存草稿按 generation_id 恢复，避免重复生成。
- 资料/项目记录变更后阻止保存过期引用，模型服务变更后阻止无提示切换。任务库仅在本机；不发送个人记忆、不进入 Git，也不作为 OneDrive 数据恢复来源。保存的正文和质量记录正常镜像。
- GPT 深入模式使用 DSH 的目录、按来源读取、查找证据和正文检查工具。禁止任意文件系统、shell、网页和子代理工具，参数不能指定路径。真实读取范围单独计数；200000字/128次调用是上限，超限不伪装全文覆盖。
- 执行边界及兼容性见 [Harness](<HARNESS.md>)。复杂 Excel 原表自动修改、任意联网核验和所有交付格式的内容质量保证仍未实现。

## 1.4.0 · 工作入口、材料整理与可继续执行的交付

- 首页“一句话说需求”自动识别工作目的，路由至研究、会议、建模或项目整理。首页支持项目选择、文件/文件夹导入；资料生成沿用研究页的单一输入区，可选择目的、来源和模型。
- 工作目的覆盖研究简报、DD、IC Memo、讨论材料、技术原理、协议审阅、访谈提纲、专家需求邮件、邮件/汇报草稿、项目更新、版本对照、Excel模型审阅和表格纪要。生成成功才保存草稿，引用与每份材料的完整/摘录覆盖明确可见；失败不伪装成完成。
- 财务模型独立保存 method/assumptions/result，可重开、修改、确定性重算和重新导出动态公式 XLSX；最多八个具名情景。复杂已导入工作簿支持基于提取证据的审阅，尚不能自动修改和原生重算任意原表。
- Word/PPT/HTML 可从同一草稿导出；协议/模型/会议任务保留各自证据与口径约束。工作流结合文件和任务类型研究、邮件表达及财务执行规则；这不是模型权重训练。详见 [任务覆盖](<WORKFLOW_COVERAGE.md>) 和 [每次修订发布 SOP](<RELEASE_SOP.md>)。

- 项目详情集中展示完整材料库，按子任务组织资料、Memo、协议、Notes、纪要、交付和行动；允许创建自定义子任务。新建、导入、修改、旧库启动及备份恢复自动整理，无需逐个设置。
- 分类依据文件名、标题、已有分类及有限正文片段；常见工作包括投委会材料、交易协议、专家访谈、基本面研究、财务与估值、会议整理。自定义子任务按名称匹配；关联 Notes/行动沿用资料/会议分组。分类由本机规则完成，不调用外部模型；语义含糊时归入项目资料，不能宣传为任意文档的模型语义理解。
- 同名材料的 v1/v2、修订/最终稿、日期等尾部标记归入项目内稳定版本组；所有记录及内容保留。版本列表明确区分导入顺序与命名标记，不自动把最后上传当成获批终版，不提供语义 diff 或引用重锚。
- 项目内自定义分组可选；默认自动整理。显式指定的分组保留，清空恢复自动分类，跨项目移动重新分类。按子任务筛选研究资料后再勾选提问，避免重复入口。
- 研究资料支持选择整个文件夹批量导入，保留相对来源路径。新上传的原文件按工作区和 SHA-256 不可变归档并经鉴权下载；修改抽取文字不会覆盖原件。重复字节去重，版本记录不合并。
- OneDrive 镜像包含原件及项目整理索引；缺失原件可在后续同步重试恢复。JSON 备份仅包含记录、抽取文字与原件引用。旧版本从未保存的原件无法补造，需重新上传。个人记忆不参与项目整理或原件归档。

## 2026-10-03 · 研究优先界面调整（当前实现）

- 首页与项目库合并为一个“研究首页”；原projects数据/关联不删，旧#projects入口兼容至#overview。首页突出基本面研究和会议整理，公司档案用于持续归集证据/访谈/判断，不要求先建立档案才能工作。
- 研究页只留一个输入区，区分资料问答、材料生成和工作区操作。资料/生成使用明确选择的证据，行动工具按服务端校验的项目和选择范围操作；不同目的保留草稿，执行时避免重复提交。
- 研究回答、研究结论和行动助手回复采用本地安全Markdown展示：标题/粗体/列表/表格/代码/安全链接；原文Markdown仍保留用于编辑、保存和导出，引用编号/引用卡片不丢。原始HTML转义，危险链接不执行。
- 通用input/textarea/contenteditable的正常粘贴不再被全局导入拦截；在非编辑区粘贴仍可快速入库。研究模板不会擅自把所选模型切换为更贵的GPT。
- 已用临时数据/新Chrome profile进行14组真实DOM交互测试，包括单输入、模式草稿、API范围、原文引用、Markdown/XSS、项目入口兼容与移动端横向溢出；这不等于截图视觉审稿或真实模型准确性benchmark。
- 继续丰富的重点应是证据/口径差异、待核实问题、公司研究的持续更新，而不是再增加重复聊天窗口或管理仪表盘。这些更完整自动化是建议后续需求，未宣称已经全部实现。

## 1. 产品定位

面向 PE / 投资研究的本地优先、单用户、AI-native 工作区。目标是把资料、证据、研究判断、访谈纪要、估值假设和交付物联系起来，而不是堆叠项目管理表单或复制一个通用聊天机器人。

核心价值链：
**项目 → 选定资料 → 原文证据与引用 → 待核实研究结论 → 访谈/模型 → Word/PDF/PPT/Excel 交付 → 后续核实行动。**

### 1.1 已确定的用户偏好
- 中文沟通，投资研究优先；自然语言是主要操作入口，尽量少填表。
- 上传支持点击、拖拽、粘贴；日常研究调用按用户选定范围直接执行，不再增加逐次“同意外发”勾选。
- 登录、CSRF、防止误恢复备份等安全措施不能借此移除。
- DeepSeek V4.1 Flash 优先用于研究问答、行动助手和纪要；GPT/DSH 等作为可选路由。
- 个人记忆 `kind=memory` 只做本机检索，不能发给任何模型；原始记忆文件不自动改写。
- 专家访谈输出参考 PV Expert Call Notes：中性 wording，保留事实/判断/传闻归属、限定条件和不同专家之间的口径差异。
- 文件集中在 OneDrive，活动数据库留本机。公开代码不得混入真实项目材料、账号密码、登录会话或隧道凭据。
- 公网通过独立 Cloudflare tunnel，采用 WorkOS 内置 `workos-user` 账号密码登录，不是 Cloudflare Access / 邮箱 OTP。密码不写本文，仅在主机本地管理。

### 1.2 明确不属于当前版本的能力
企业多用户/RBAC、审计合规系统、自动事实核验、自动 OCR、录音/语音识别、双向跨设备数据库同步、完整三表及多层债务 LBO、从任意资料全自动生成投委会级 IC deck。不能用“已有导出”宣传这些能力已经完成。

## 2. 用户、使用场景与运行条件

| 场景 | 目标 | 当前路径 |
|---|---|---|
| 主机电脑日常研究 | 低步骤整理资料并保留证据 | 本机 `http://127.0.0.1:18866/` |

## 4. 核心流程及验收标准

### F02：资料导入
1. 选择项目，可点击选文件、拖拽，或把文本导入研究库。单文件上限约20MB（前后端字节口径略有不同，不能按20MiB边缘值承诺必过）；抽取内容有安全大小上限。
2. 抽取文本和元数据写入本机资料记录；PDF 尽量保留真实页码；DOCX/TXT 等使用段落序号，不能编造 Word 页码。
3. PPTX 读文本；XLSX/XLSM 读公式及缓存值，不刷新外链、不执行宏、不等于真实重算。
4. 正确空白/不支持文件/损坏或超限文件给出可理解错误，不半途宣称已完整导入。
5. 新上传研究资料保存原件并可重新下载；抽取文字的编辑不覆盖原件。旧资料及纯文本手工创建记录没有可补造的原件，界面仅显示实际存在的归档信息。

**已修复并做浏览器回归：** input/textarea/select/contenteditable内正常粘贴不触发导入；非编辑区或明确导入操作才入库。后续必须保留该边界。

### F03：研究问答
- 用户明确选中资料/项目后请求分析；不默认把全库、个人记忆或无关目录交给模型。
- 词法命中返回少量相关片段；未命中时按明确选择的资料公平取真实节选，总正文预算24000字符，保留 document_id、页码/段落、摘录及 [S#] 编号。空正文不会虚构引用。
- 无资料时可选择资料，或明确选择一般解释；一般解释与资料支持的项目事实分开。模型常识不冒充来源，节选不表示全文已读。
- 服务端可检查 [S#] 是否超出范围；这不是“引用内容支持结论”的语义验证，更不是事实核验。
- 保存结论时保留摘录及来源；默认待核实。界面读的是抽取文本，不是原始文件阅读器。
- 验收：无依据数字不应由系统默认为已核实；点击引用能定位到相应摘录；memory 在模型调用前被硬性拒绝。

### F04：行动助手
工具含 import_text、create_project、create_note、create_task、create_meeting、draft_deliverable、search、list_projects、organize_project、create_subtask、run_workflow、generate_minutes。工具改动留下工作区记录。生成材料只用调用者明确选择的资料；纪要工具只处理明确选择的现有会议，不让模型执行任意文件或 shell 指令。来自客户端的历史回复没有可证明的证据归属，不自动发给行动模型。

### F05/F06：专家纪要
- 原文转写可粘贴或拖入支持的文件，保存 transcript；不是音频→文本服务。
- 输出结构：专家机构/职位/日期；专家背景；关键点评；按主题的访谈内容及 • / o / ➢ 层级。
- 不补造专家身份、任职时间、公司、数字；缺失写“未提及”；保留条件、传闻/判断归属，不合并不同专家矛盾观点。
- 多专家比较目前为竖版两列「议题 / 专家口径」逐专家展开，**不是用户样本中横向多列矩阵的逐像素复刻**。4+专家生成目录，页码通过书签/PAGEREF 取得，不用每位专家一页的猜测。
- experts/matrix/contents 已持久化，重开和备份恢复后可导出。单独手动修改 summary 会失效旧结构，避免导出覆盖人工修改；需要重新生成或未来增加结构化编辑器才能恢复比较表。
- DOCX 参考 A4、中文楷体/英数字 Arial、标题14pt/正文10pt；具体 heading、表格宽度和长文本仍需图像/真实 Office 视觉审阅。
- 输出 DOCX/PDF 必须可打开；PDF 只走已配置的 bundled LibreOfficeKit，不自动寻找替代 Office 程序。Kit 缺失不影响 DOCX，但 PDF 应清楚报错。
- 验收：真实页码域与 PDF 正文一致；源转写、人工修订和导出内容不得错位；年份、型号、前导零、小数和中文单位空格不能被数字格式器改坏。

### F07/F08：估值与回报
**计算原则：AI 只提取明确假设，算术交由 Python；缺失输入不自动当零。**
- P/E：规范化净利润 × P/E → 股权价值；可选稀释后股数。负净利润不强行计算普通 P/E。
- P/S：收入 × 股权 P/S → 股权价值；净债务可桥接隐含 EV。不是 EV/Sales 口径。
- DCF：逐年 EBIT 或收入×利润率、税、D&A、CapEx、ΔNWC → FCFF；WACC、年末/年中折现、永续/退出倍数终值、净债务及少数股东权益桥。
- LBO：进入 EV/债务/费用/最低现金/初始现金/滚存；单层逐年利息/税/强制偿还/cash sweep/现金债务；退出倍数/费用；按真实进入退出日期算 IRR/MOIC。资金缺口明确警示。
- LBO 期初现金由交易出资支持并计入资金用途；最低现金在偿债和 cash sweep 后保留。Sponsor 和卖方滚存按期初普通股出资比例分配退出回收，假设同权、不含特殊分配瀑布；全部收益守恒。每预测行须对应一个完整年度，年度数量/连续标签与持有日期不符时拒绝，不悄悄拿一年经营现金流算多年回报。
- 当前无期间分红、债务 tranches、循环利息、ESOP/IPO dilution、完整三表联动等，不能称为完整投行模型。
- 自然语言假设整理使用统一模型列表中的选定服务，默认 WorkBuddy DeepSeek V4.1 Flash；缺少关键条件时继续追问并保留当前假设。模型提取值仍需核对；source_notes 为用户/模型提供元数据，不是已验证的原文映射。
- Excel 应链接可编辑输入，输出分为实时公式与原始 Python 快照；修改退出倍数/费用、继承税/利率和日期等应联动。已经用10份原始/修改后工作簿真实重算，与 Python 引擎核对。
- 边界：收入×EBIT margin 在导出时会物化成 EBIT 数字，不代表经营预测全部字段已动态联动；方法/结构改变通常要重新生成工作簿。
- **保存模型**独立持久化 method/assumptions/result，服务端从假设重算，不信任客户端结果缓存。保存后可重开、修改、比较最多八个具名情景，重新导出 XLSX。旧body-only记录仍可读，不假装已具备结构化模型。情景不能仅改币种/单位/期间标签；原始假设不被覆盖。

### F09/F10：交付中心
- 正文继续编辑，导出前保存；HTML 可编辑/批注，保存的是独立副本，不回写平台数据。
- PPTX 保留所有文本并自动续页；超过200内容页明确拒绝，不截断。Markdown 表格为可编辑 native table，最长表自动续页，1–6列/单元格160字符的限制会报错而非隐藏值。
- 明确 chart JSON 支持 column/bar/line，带 native chart 和 Excel 数据；分类/系列数量一致且每值为有限数，不把空值当零，不执行 JSON 字符串。
- 保留来源标签/notes；数据需要由用户/研究流程明确提供。完整 IC deck 所需的 storylining、证据映射、可比公司/交易表、品牌模板适配等为后续范围。
- 已保存产物可自动归档至关联项目的 `WorkOS产物`，展示实际文件与失败状态；浏览器下载仍可单独使用。OneDrive记录镜像中的Outputs文本不等于这些导出文件，云端上传状态不由本机写入推断。

## 7. 安全与运行要求

- 公网固定HTTPS；后端仍监听回环18866，不将Python服务直接绑定0.0.0.0。
- 当前运行 `WORKOS_PUBLIC_AUTH_MODE=password`；legacy Access mode 可选，但不等于当前部署采用 Access。
- 用户 `workos-user`；密码只在主机管理；仅存随机盐PBKDF2-SHA256（600000次）哈希。登录会话标识哈希本机存储，不能同步至OneDrive/Git。
- Cookie 为 Secure / HttpOnly / host-only；不记住12小时、记住7天，并跨应用重启保留；注销/重设密码使会话失效。
- 登录提交前自动获取新nonce/cookie；挑战失效可自动恢复一次，明确提示Cookie阻止；换网/IPv4/IPv6不硬性绑定挑战IP（IP仅用于限流），仍有来源约束、失败限流；公网全部数据API/下载需登录，写入仍校验每session CSRF；本机可信请求不需要公网登录。
- `/auth/setup` 仅本机、需本机CSRF；不能通过公网初始化/重设密码，包括Host被改写为localhost的转发请求。
- 不记录密码/token/原始鉴权header；不读取Chrome cookie当作Cloudflare或GitHub授权。
- 不触碰共享dsh tunnel；独立WorkOS连接器重复启动应幂等；启动设置不包含明文密码。
